# Architecture Decision Records

ADRs record decisions that significantly affect implementation, support, or
operability. They do not duplicate API documentation or implementation plans.

## Record format

Each ADR should contain:

1. **Status:** Proposed, Accepted, Deprecated, or Superseded.
2. **Context:** The problem and constraints.
3. **Decision:** The selected approach, once known.
4. **Consequences:** Benefits, costs, and follow-up work.
5. **Alternatives:** Options considered and why they were not selected.
6. **Related work:** Links to architecture, milestones, and spikes.
